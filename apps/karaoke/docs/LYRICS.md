# 로컬 가사 사용법

이 앱은 가사를 저장소·빌드·서버 응답에 포함하지 않는다. 사용자가 선택한 파일은
브라우저 IndexedDB에 저장되며, 앱의 가사 기능은 내용을 운영자 서버나 외부 가사 API에 업로드하지 않는다.
음원 재생에는 별도의 YouTube iframe API가 사용된다.

## 파일 형식

기존 배열 형식을 그대로 쓸 수 있다.

```json
[
  {
    "time": 12.3,
    "jp": "歌の練習",
    "pron": "우타노 렌슈",
    "ko": "노래 연습"
  }
]
```

- `time`: 줄이 시작되는 초. 0 이상의 숫자
- `jp`: 일본어 원문. 필수
- `pron`: 한글 발음. 없으면 빈 문자열 또는 생략
- `ko`: 한국어 번역. 없으면 빈 문자열 또는 생략

`time`은 앞줄보다 반드시 커야 하며 중복될 수 없다. 앱은 순서가 잘못된 파일을 조용히
재정렬하지 않고 오류로 돌려준다. 한 곡은 최대 5,000줄, 파일 하나는 최대 2MB다.
앱이 내보낸 전체 라이브러리 백업은 최대 50곡·24MB까지 다시 불러올 수 있다.
내보낸 백업이 그대로 다시 들어오도록 로컬 보관함도 50곡으로 제한한다. 여러 파일을
함께 고를 때도 선택 전체의 합계는 24MB로 제한한다.

빈 가사 화면에서 현재 곡으로 불러올 때는 파일 이름과 무관하게 현재 선택된 곡에 저장한다.
`이 앱에 대해 → 내 가사 보관함`에서 곡별 파일을 직접 복원할 때만 파일 이름을
`src/songs/`에 등록된 slug와 맞춘다.

```text
kaiju-no-hanauta.json
odoriko.json
```

파일 이름을 자유롭게 쓰고 싶으면 JSON에 slug를 명시한다.

```json
{
  "slug": "odoriko",
  "lyrics": [{ "time": 12.3, "jp": "歌の練習" }]
}
```

## 폰에 불러오기

1. 본인이 개인적으로 사용할 파일을 폰의 Files, iCloud Drive 또는 로컬 저장소에 둔다.
2. 빈 가사 화면의 `이 곡의 JSON 불러오기`에서 현재 곡용 파일 한 개를 선택한다.
3. 여러 곡을 옮길 때는 기존 기기의 `백업 내보내기`로 만든 파일 한 개를 새 기기의
   `이 앱에 대해 → 내 가사 → 백업 또는 가사 파일 불러오기`에서 선택한다.
4. 기존 곡을 바꾸는 경우 확인 창에서 교체를 승인한다.

저장 후에는 새로고침하거나 PWA를 다시 열어도 유지된다. 앱 셸을 한 번 캐시했다면
가사 표시는 오프라인에서도 가능하다. YouTube 재생에는 네트워크가 필요하다.

`내 가사 → 백업 내보내기`는 이 브라우저에 저장된 모든 곡을 재가져오기 가능한 JSON 한
개로 내려받는다. 브라우저 사이트 데이터를 지우거나 기기를 옮기기 전에 백업해 두고,
복원할 때는 `백업 또는 가사 파일 불러오기`에서 선택한다.
앱의 곡 목록이 바뀐 뒤 오래된 백업을 불러와도 목록에서 사라진 곡을 버리지 않는다.
해당 곡은 화면에 노출하지 않고 보존용 레코드로 저장하며, 다음 전체 백업에도 다시 포함한다.

`내 가사 → 저장된 가사 관리`에서 곡 하나만 지우거나 저장된 가사를 전부 제거할 수 있다.
두 작업 모두 백업이 없으면 되돌릴 수 없으므로 확인 창을 거친다.

## 앱에서 싱크 만들기

컨트롤 줄의 종이·연필 아이콘을 누른다.

1. `일본어 원문`에 노래에서 부르는 일본어 가사만 줄 단위로 붙인다.
2. `이 원문으로 가사 만들기`를 눌러 편집 화면으로 이동한다. 준비된 JSON이나 LRC가 있다면
   `이미 JSON·LRC가 있어요`에서 붙여 넣을 수 있다.
3. 외부 AI 요청문 복사는 제출 권한이 있는 원문에만 쓰는 선택 기능이며, 서비스 정책에 따라 거절될 수 있다.
4. 적용 후 편집 화면에서 시간이 모두 들어왔는지 확인한다. 시간이 비어 있는 줄만
   재생·5초 이동·탐색 막대로 구간을 찾는다.
5. 각 줄이 시작되는 순간 `지금 이 줄 시작`을 누른다. 이미 찍은 줄을 다시 선택하거나 시작 시간을
   직접 입력해 보정할 수 있다.
6. 모든 줄을 찍고 `이 기기에 저장`을 누른다.
7. 저장 직후 `JSON 백업 복사`로 현재 초안을 보관하거나, `내 가사 → 백업 내보내기`로
   전체 라이브러리를 파일로 저장한다.

앱의 저장 동작은 현재 곡의 IndexedDB 레코드에만 반영된다. 백업 복사는 사용자가
명시적으로 누른 경우에만 slug가 포함된 단일 곡 JSON을 클립보드에 기록하므로 파일 이름과
무관하게 다시 불러올 수 있다. 곡을 바꾸면 편집기도 새 인스턴스로 바뀌어 다른 곡에 잘못
저장되지 않는다.

## 재생목록과 새 곡 추가

가사를 추가하는 작업과 곡 메타데이터를 추가하는 작업은 분리한다.

1. 상단의 현재 곡 제목을 눌러 곡 목록을 연다.
2. 왼쪽 뒤로 버튼에서 재생목록을 선택하거나 새로 만든다.
3. 곡 목록의 + 버튼에서 YouTube 영상 주소, 원어 제목, 한국어 표기를 입력한다.
4. 추가한 곡을 연 뒤 빈 가사 화면이나 가사 편집 버튼에서 가사를 저장한다.

곡 제목은 YouTube 영상 제목에서 자동 추측하지 않는다. 사용자가 입력한 제목과 영상 ID,
재생목록 순서만 브라우저에 저장하며 가사 원문은 저장소나 앱 배포물에 넣지 않는다.
곡 정보의 연필 버튼에서 제목을 다시 고칠 수 있고, About의 `재생목록 초기화…`는
재생목록과 곡 정보만 기본 상태로 되돌리며 이미 저장한 가사는 보존한다.

## 배포 안전장치

다음 검사는 `public/lyrics`에 파일이 있으면 확장자와 관계없이 실패한다. 실수로 다른
경로에 둔 JSON·LRC·SRT·VTT·TXT·YAML 가사 데이터도 막으며, 코드에서 명시적으로
허용한 두 폰트 OFL 고지만 예외로 둔다.

```bash
pnpm --filter karaoke check:no-lyrics
```

프로덕션 빌드는 시작 전 `public`, 완료 후 `dist`를 모두 검사한다. 서비스워커도 `/lyrics`
요청을 처리하거나 캐시하지 않으며, `v3-local-first` 활성화 시 과거 가사 캐시를 제거한다.
빌드가 주입하는 프리캐시는 JS/CSS·manifest·icons·license로 제한하고, 분할 일본어 폰트는 실제로
첫 화면에서 사용된 조각만 추가 캐시한다. 셸과 프리캐시 파일 콘텐츠로 만든 build ID별 새 캐시에
설치를 끝낸 뒤 이전 karaoke 캐시를 지우므로, 실패한 업데이트가 기존 오프라인 셸을 섞거나
덮어쓰지 않는다.
