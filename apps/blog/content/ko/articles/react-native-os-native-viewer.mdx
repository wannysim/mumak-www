"문서함에서 파일을 누르면 전체화면으로 열리게 해줘."

요구는 이 한 문장이 전부였다. 쉬워 보였다.

그런데 문서함을 열어보니 성격이 전혀 다른 두 종류가 섞여 있었다. 하나는 리모델링 문서 — 서버에 올라간 실제 이미지·PDF 파일. 다른 하나는 계약서 — 전자계약 웹페이지 URL이다. 목록에선 둘 다 똑같이 한 줄로 보이지만, "연다"는 동작의 의미는 완전히 달랐다.

이 한 문장이 결국 iOS 네이티브 코드를 직접 한 조각 짜는 데까지 이어졌다. React Native가 처음이면 "왜 그렇게까지 해야 하나"가 안 와닿을 수 있는데, 이 글은 그 "왜"를 따라간 기록이다.

> 결론부터. 파일(이미지·PDF)은 **OS 파일 뷰어**로, 계약서(웹 URL)는 **OS 인앱 브라우저**로 연다. 성격이 다르니 경로를 갈랐고, iOS엔 파일 뷰어를 띄울 기성 API가 없어 **Swift 모듈을 직접** 놨다.

## 1. 한 문장이 둘로 갈라지다

목록에선 같아 보여도, "연다"가 가리키는 건 둘이 달랐다.

| 종류          | 실체                       | 원하는 경험                        |
| ------------- | -------------------------- | ---------------------------------- |
| 리모델링 문서 | 실제 **파일**(jpg·png·pdf) | OS 기본 뷰어로 전체화면 미리보기   |
| 계약서        | 전자계약 **웹 URL**        | 공유·"브라우저로 열기"가 되는 화면 |

처음엔 둘 다 그냥 WebView — 앱 안에 띄우는 작은 브라우저 컴포넌트 — 로 열려고 했다. 한 컴포넌트로 끝나니 깔끔해 보였다. 그런데 둘 다 어딘가 어긋났다.

- 파일을 WebView로 열면 OS 뷰어 느낌이 안 났다. 우리가 만든 커스텀 헤더가 얹히고, 핀치 줌이나 공유 같은 기본 동작이 어설펐다.
- 계약서를 우리 WebView로 열면 공유 버튼도, "기본 브라우저로 열기"도 없었다. 사용자 입장에선 답답한 반쪽짜리 브라우저였다.

결론은 하나였다. **OS가 이미 갖고 있는 진짜 뷰어와 진짜 브라우저를 쓰자.** 그러려면 파일과 URL의 경로를 처음부터 갈라야 했다.

```text
리모델링 문서 = 파일 → 파일 뷰어가 필요   (로컬로 내려받아 보여줘야 함)
계약서        = URL  → 브라우저가 필요     (주소만 넘기면 됨)
```

이 갈림을 이해하려면, React Native가 OS 기능을 어떻게 부르는지부터 알아야 한다.

## 2. React Native에서 "OS 기능을 부른다"는 것

React Native 앱은 두 세계로 나뉜다.

- **JS 세계**: 우리가 쓰는 React 코드. 화면·상태·로직. JavaScript 엔진(Hermes) 위에서 돈다.
- **네이티브 세계**: 실제 iOS(Swift)·Android(Kotlin) 코드. 카메라·키체인·파일 뷰어 같은 OS 기능은 전부 여기 있다.

둘은 **브리지**로 연결된다. JS에서 네이티브 함수를 부르면 브리지를 건너 네이티브 코드가 실행되고, 결과가 다시 JS로 돌아온다. 이 왕복은 비동기다 — 그래서 네이티브를 부르는 코드는 거의 다 `async/await`다.

여기서 이 글 전체를 관통하는 한 문장이 나온다.

> **JS는 OS 기능을 직접 못 한다. 네이티브 쪽에 "다리"가 놓여 있어야 부를 수 있다.** 다리가 이미 있으면(라이브러리) 그냥 쓰고, 없으면 직접 놓는다.

Android 쪽은 다리가 다 있었다. iOS 파일 뷰어는, 없었다. 4장이 그 이야기다.

## 3. 파일은 먼저 내려받아야 한다

OS 파일 뷰어는 "로컬 파일"을 받는다. 원격 URL을 직접 못 여니, 양쪽 플랫폼 공통으로 **먼저 캐시에 내려받는다.**

```ts
const target = `${FileSystem.cacheDirectory}${toSafeFileName(doc.fileName)}`;
const { uri } = await FileSystem.downloadAsync(doc.url, target);
```

작은 디테일 하나. 저장할 파일명을 **원본 이름 그대로** 쓰면, OS 뷰어 헤더에 그 이름이 그대로 뜬다. 사용자가 목록에서 보던 이름이 뷰어 상단에 똑같이 나오는 것이다. 대신 파일시스템에 위험한 문자(`/ \ ? % * : | " < >`)만 `_`로 치환했다 — 그게 `toSafeFileName`이다.

내려받았으면 띄울 차례다. 여기서 OS가 갈린다.

## 4. iOS — Quick Look, 없어서 직접 놓은 다리

iOS엔 `QLPreviewController`라는 OS 기본 전체화면 미리보기가 있다. 메일에서 첨부를 누르면 뜨는 그 화면 — 파일명 헤더, "완료" 버튼, 공유 버튼이 다 들어간 네이티브 뷰어다. 우리가 원하던 경험 그대로다.

문제는, **이걸 띄우는 JS API가 React Native에도 Expo에도 없었다.** 2장에서 말한 "다리가 없는" 경우다. 그래서 직접 놨다.

로컬 Expo 모듈은 네 조각으로 이뤄진다.

```swift
// modules/quick-look/ios/NativeQuickLookModule.swift (핵심만)
AsyncFunction("presentAsync") { (uri: String, promise: Promise) in
  let previewController = QLPreviewController()
  previewController.dataSource = self.dataSource   // 보여줄 파일 1개
  presentingVC.present(previewController, animated: true) { promise.resolve(nil) }
}
```

- `NativeQuickLookModule.swift` — Apple의 `QLPreviewController`를 실제로 띄우는 코드
- `NativeQuickLook.podspec` — Xcode가 이 Swift를 앱에 컴파일하도록 알려주는 설정
- `expo-module.config.json` — Expo가 "여기 네이티브 모듈 있다"고 자동 인식(autolinking)하게 하는 선언
- `src/native/quickLook.ts` — JS 쪽 래퍼

JS 래퍼가 이 다리의 입구다.

```ts
// 네이티브 모듈을 "있으면 가져오고, 없으면 null"
const QuickLook = requireOptionalNativeModule<{
  presentAsync: (uri: string) => Promise<void>;
}>('NativeQuickLook');

export const isQuickLookAvailable = () => QuickLook != null; // iOS 네이티브 빌드에서만 true
export const presentQuickLook = (uri: string) => QuickLook!.presentAsync(uri);
```

포인트는 `requireOptionalNativeModule`이다. **있으면 쓰고, 없으면 null**을 돌려준다. Android엔 이 모듈이 없으니 `null` → 호출부가 자연스럽게 Android 경로로 흘러간다. 한 코드베이스가 iOS·Android·Expo Go에서 크래시 없이 도는 비결이 이 패턴이다.

참고로 `ios/`·`android/` 네이티브 프로젝트는 Expo가 설정을 보고 자동 생성(`expo prebuild`)하므로 보통 git에 안 올린다. 하지만 이렇게 **직접 손으로 쓴 모듈 소스**(`modules/quick-look/...`)는 생성물이 아니라서 git으로 추적해야 한다 — `.gitignore`에 "이건 무시하지 마"라는 예외를 넣었다.

## 5. Android — Intent와 content:// 함정

Android엔 Quick Look 같은 인앱 전체화면 뷰어가 없다. 대신 시스템에 "이 파일 좀 봐줄 앱 불러줘"라고 요청하는 표준 방법이 있다 — `Intent.ACTION_VIEW`. 이미지면 사진 앱, PDF면 PDF 뷰어가 뜬다.

여기 함정이 하나 있다. 요즘 Android는 보안상 `file://` 경로를 다른 앱에 직접 넘기면 `FileUriExposedException`으로 막는다. 그래서 `file://`를 **`content://` URI로 바꿔서**, "이 URI 읽을 권한 줄게"라는 플래그와 함께 넘겨야 한다.

```ts
const contentUri = await FileSystem.getContentUriAsync(uri); // file:// → content://
await IntentLauncher.startActivityAsync('android.intent.action.VIEW', {
  data: contentUri,
  flags: 1, // FLAG_GRANT_READ_URI_PERMISSION (읽기 권한 부여)
  type: doc.mimeType, // image/* · application/pdf — 어떤 앱을 띄울지 힌트
});
```

iOS와 달리 여기선 Swift를 짤 필요가 없었다. `expo-intent-launcher`(Intent 발사)와 `expo-file-system`(content URI 변환)이 **다리를 이미 놔줬기** 때문이다. 있는 건 쓰고, 없는 것만 만든다 — 2장의 그 원칙 그대로다.

## 6. 하나의 open(doc)으로

플랫폼이 갈려도 화면 코드까지 갈릴 이유는 없다. JS 쪽에선 이 모든 걸 훅 하나(`useDocumentViewer`)로 감췄다. 화면은 그냥 `open(doc)`만 부른다.

```ts
const { uri } = await FileSystem.downloadAsync(doc.url, target);

if (isQuickLookAvailable()) {
  // iOS — 네이티브 모듈이 있다
  await presentQuickLook(uri);
  return;
}
if (Platform.OS === 'android') {
  // Android
  const contentUri = await FileSystem.getContentUriAsync(uri);
  await IntentLauncher.startActivityAsync('android.intent.action.VIEW', {
    data: contentUri,
    flags: 1,
    type: doc.mimeType,
  });
}
```

같은 `open(doc)` 한 번이 iOS에선 Quick Look으로, Android에선 시스템 뷰어로 갈라진다. **한 번의 JS 호출, OS마다 다른 네이티브 경험** — 크로스플랫폼 코드의 전형이다.

## 7. 계약서는 파일이 아니다

이제 남은 절반, 계약서. 이건 파일이 아니라 전자계약 웹페이지 URL이다. 파일 뷰어로는 못 연다. 그렇다고 우리 WebView로 열면 — 1장에서 봤듯 — 공유도, 주소창도, "기본 브라우저로 열기"도 없다.

답은 OS가 주는 **인앱 브라우저**다. 한 줄이면 된다.

```ts
await WebBrowser.openBrowserAsync(url);
// iOS → SFSafariViewController, Android → Chrome Custom Tabs
```

이 한 줄이 따라오는 것들:

- 공유 버튼, "기본 브라우저(Safari/Chrome)로 열기", 주소 표시, 리더 모드
- 시스템 수준 쿠키·세션 — 맨몸 WebView에서 나던 "흰 화면"도 이걸로 대부분 사라졌다

> "앱 안에서 웹 보여주기"에도 두 층위가 있다.
> ① `react-native-webview` — 우리가 UI를 직접 그리는, 약관처럼 단순 표시용
> ② OS 인앱 브라우저(`expo-web-browser`) — 공유·브라우저 연동이 필요할 때
> 계약서는 ②가 맞았다.

## 8. 가로지르며 남은 원리들

기능을 다 붙이고 나니, 파일이냐 URL이냐와 무관하게 가로지르는 React Native 원리 몇 개가 남았다.

### 있으면 쓰고 없으면 흘려보낸다

`Platform.OS`로 갈래를 나누되, "이 기능이 없으면 다음 경로로" 부드럽게 떨어지게 설계한다(graceful degradation). `isQuickLookAvailable()`이 false면(Android·Expo Go) 자연히 Android 경로로 가는 식이다. optional 네이티브 모듈 패턴이 이걸 가능하게 한다 — JS와 네이티브가 느슨하게 묶인다.

### JS ↔ 네이티브는 항상 비동기 경계

`presentAsync`, `downloadAsync`, `startActivityAsync` — 네이티브 호출은 전부 `await`다. 브리지를 건너는 일이라 동기로 다룰 수 없다.

### 동시성 가드는 state가 아니라 ref로

"이미 처리 중이면 무시"(중복 탭 방지)를 처음엔 `useState`로 막았다. 그런데 빠르게 두 번 누르면 가끔 둘 다 통과했다. **`setState`는 비동기**라, 두 번째 탭이 "아직 안 바뀐" 상태를 보고 지나가버린 것이다.

```ts
const isOpeningRef = useRef(false); // 동기 가드: 즉시 잠금
const [openingId, setOpeningId] = useState<string | null>(null); // 렌더용: 스피너 표시

async function open(doc) {
  if (isOpeningRef.current) return; // ref는 즉시 반영 → 레이스 없음
  isOpeningRef.current = true;
  setOpeningId(doc.id);
  try {
    /* 다운로드 → 뷰어 */
  } finally {
    isOpeningRef.current = false;
    setOpeningId(null);
  }
}
```

**렌더에 영향 주는 값은 state, 지금 당장 읽어야 하는 플래그는 ref.** 둘의 역할을 섞지 않는다.

### 화면에 보여줄 이름 ≠ 기능에 넘길 이름

목록에 뜨는 이름은 확장자를 뗀 `displayName`을, OS 뷰어 헤더엔 확장자까지 붙은 원본 파일명을 쓴다. 같은 문서라도 "보여줄 데이터"와 "기능에 넘길 데이터"는 다를 수 있다 — 작지만 자주 놓치는 모델링 포인트다.

## 9. 코드를 짠다 ≠ 앱이 돈다

웹은 저장하면 끝이다. 네이티브 앱은 OS·서명·기기라는 현실을 한 번 더 통과해야 한다.

가장 먼저 부딪힌 규칙은 이거였다.

```text
네이티브 변경(모듈·capability·config plugin) → 다시 빌드해야 반영된다
JS 변경 → 핫리로드(Fast Refresh)로 충분
```

이번엔 Swift 모듈과 네이티브 패키지를 새로 넣었으니, JS만 고치던 평소와 달리 빌드를 한 번 다시 돌려야 했다.

그 외에 네이티브 앱이라서 따라온 것들:

- **코드 서명**: iOS 앱은 서명이 있어야 기기에서 돈다. 시뮬레이터는 임시(ad-hoc) 서명으로 충분하지만, 서명이 아예 없으면 키체인이 막혀 로그인 세션조차 안 잡힌다.
- **정적 프레임워크 빌드**: 일부 네이티브 의존성은 static linking 설정이 맞아야 컴파일된다. 설정이 네이티브 프로젝트에 반영 안 돼 있으면 `prebuild` 재생성으로 동기화한다.
- **에뮬레이터 ↔ Metro 연결**: Android 에뮬레이터는 호스트 PC의 Metro에 바로 못 붙어 `adb reverse tcp:8081 tcp:8081`로 포트를 이어줘야 한다.
- **딥링크로 화면 검증**: `myapp://document-category/renovation` 같은 URL로 특정 화면에 바로 진입해 테스트한다.

즉 "코드를 짰다"와 "앱이 돈다" 사이엔 빌드·서명·기기 환경이 한 묶음으로 끼어 있다. 웹에서 넘어오면 이 간극이 가장 낯설다.

## 마치며

한 문장짜리 요구("파일 누르면 열리게")에서 시작해, 데이터 성격으로 경로를 가르고, 없는 다리는 직접 놓는 데까지 왔다. 줄이면 네 가지다.

- **문제를 성격으로 가른다.** "열기"라는 한 단어도 파일이냐 URL이냐에 따라 구현이 완전히 갈린다.
- **있는 건 쓰고, 없는 것만 만든다.** iOS Quick Look은 기성 API가 없어 100줄 남짓한 Swift 모듈을 직접 놨고, Android Intent·다운로드·인앱 브라우저는 기성 라이브러리로 충분했다.
- **한 번의 JS 호출, OS별 네이티브 경험.** `Platform.OS`와 optional 모듈로 분기하고, 없으면 다음 경로로 흘려보낸다.
- **React 원리도 빠지지 않는다.** 동시성은 ref로 동기 가드, 렌더용 값은 state — 역할을 나눈다.

이번에 쓴 도구를 한눈에:

| 목적                                  | 도구                                                             |
| ------------------------------------- | ---------------------------------------------------------------- |
| 원격 파일 다운로드 · content URI 변환 | `expo-file-system`                                               |
