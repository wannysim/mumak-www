## 읽는 순서 제안

URL 입력부터 화면까지를 큰 지도로 먼저 읽고, HTTP 버전 → 캐싱으로 프로토콜을 깊게 판 뒤,
CORS → XSS·CSRF로 보안 모델을 묶어 읽는 흐름을 권한다.
XSS·CSRF를 읽었다면 실전 사례 둘 — script 안의 JSON(XSS의 변종)과
OAuth 콜백 보안(CSRF의 변종) — 으로 이어 읽으면 일반론이 손에 잡힌다.
인증을 처음부터 잡고 싶다면 세션 vs 토큰으로 증표의 본질을 먼저 세우고,
그 위에서 Access + Refresh 토큰 패턴으로 실전 구현(메모리 + httpOnly 조합)까지 이어 읽는 흐름을 권한다.
OAuth/OIDC 쪽은 state로 콜백을 먼저 이해하고, Authorization Code와 ID Token의 차이를 잡은 뒤,
nonce로 ID Token 자체를 묶는 방식까지 이어 읽으면 "state와 nonce가 뭐가 다른데?"라는 질문이 정리된다.
모바일 앱 소셜 로그인까지 이어지면, provider의 idToken과 우리 서비스 refreshToken의 책임을 분리해서 읽으면 좋다.
