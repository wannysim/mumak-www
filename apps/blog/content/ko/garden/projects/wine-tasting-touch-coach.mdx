[[digital-garden-expansion-plan|디지털 가든]]에 남겨두는 앱 아이디어 메모.
이건 단순한 와인 기록 앱보다, *와인을 마시는 경험 자체를 더 펜시하게 만들어주는 인터랙티브 코치*에 가깝다.

## 한 줄 정의

사용자가 자연어로 길게 쓰지 않아도, _터치만으로 간편하게 테이스팅을 기록하고_, 기록이 쌓일수록 내 세계지도와 취향 지도가 점점 더 선명해지는 앱.

## 핵심 컨셉

- 메인은 자유 입력이 아니다.
- 사용자는 버튼, 칩, 슬라이더, 스와이프 같은 *가벼운 터치*만 한다.
- 앱은 선택지를 점점 더 세밀하게 열어주면서, 사용자를 자연스럽게 깊은 테이스팅으로 유도한다.
- 동시에 사용자가 마신 와인의 **와이너리/산지/국가**를 지도에 누적해서 보여준다.
- 매번 마실 때마다 지도가 조금씩 색칠되고, 내 취향의 지리적 범위가 넓어지는 느낌이 핵심이다.

## 지도 기반 경험

이 앱의 재미는 "무슨 와인을 마셨는가"를 넘어서, "내가 어디까지 마셔봤는가"를 시각화하는 데 있다.

### 1) 세계 지도

- 와이너리의 국가와 대륙을 보여준다.
- 마실 때마다 국가 단위 커버리지가 넓어진다.
- 처음 보는 산지일수록 지도에서 더 강한 피드백을 준다.

### 2) 국가/지역 지도

- 프랑스면 보르도, 부르고뉴, 론처럼 세부 산지로 들어간다.
- 이탈리아면 피에몬테, 토스카나처럼 구역 단위로 채운다.
- 지역별로 색이 쌓이면서 "어느 산지를 많이 마셨는지" 한눈에 보인다.

### 3) 개인 취향 지도

- 실제 지도가 아니라도 된다.
- 내가 자주 마시는 산지/품종/스타일을 한 장의 커버리지 맵처럼 보여줄 수 있다.
- 예: 구세계 vs 신세계, 산미 중심 vs 바디 중심, 레드 vs 화이트 비중.

## 지금까지 정리한 방향

- 와인 경험을 더 펜시하게 만드는 앱이다.
- 테이스팅 기록은 자연어보다 _터치_ 중심으로 빠르게 남긴다.
- 기록이 쌓일수록 세계지도, 지역 지도, 취향 지도가 점점 더 채워진다.
- 모바일과 웹은 따로 놀지 않고, 같은 웹앱/웹뷰 경험으로 맞춘다.
- 이 프로젝트는 UI/UX 비중이 높아서 기획/디자인 보조가 같이 필요하다.

## UX 방향

### 1단계: 감각의 큰 덩어리

처음엔 아주 단순하게 시작한다.

- 가벼움 / 중간 / 묵직함
- 산뜻함 / 균형 / 진함
- 과일 / 꽃 / 허브 / 나무 / 스파이스

### 2단계: 선택에 따라 더 깊게

예를 들어 사용자가 *과일*을 고르면 다음엔:

- 시트러스
- 사과 / 배
- 베리
- 잘 익은 과일

사용자가 *산미 높음*을 고르면 다음엔:

- 날카로운 산미
- 생동감 있는 산미
- 상큼한 산미

이런 식으로, *처음엔 쉬운 말*로 시작해서 *나중엔 더 정교한 표현*으로 들어간다.

### 3단계: 앱이 정리

마지막엔 사용자가 누른 선택들을 바탕으로 앱이:

- 테이스팅 노트 요약
- 비슷한 와인 추천
- 내 취향 프로필 반영
- 해당 와인의 와이너리/산지 색칠

까지 해준다.

## 제품 스펙 초안

### 핵심 사용자 흐름

1. 와인을 기록한다.
2. 앱이 와인 메타데이터를 가져오거나 수동 입력을 받는다.
3. 테이스팅 질문이 1개씩 나온다.
4. 사용자는 터치로 답한다.
5. 테이스팅 노트가 저장된다.
6. 지도 3종이 함께 업데이트된다.

### 필수 데이터 필드

- 와인명
- 생산자 / 와이너리
- 국가
- 지역 / 서브리전
- 품종
- 빈티지
- 테이스팅 태그
- 내 평점
- 마신 날짜

### 첫 버전 MVP

- 와인 추가
- 와이너리 위치 자동 매핑
- 세계 지도 / 지역 지도 / 취향 지도 3종 표시
- 터치 기반 테이스팅 질문 플로우
- 기록 리스트
- 개인 통계

### 나중에 붙일 수 있는 것

- 블라인드 테이스팅 모드
- 라벨 사진 OCR
- 친구와 비교하는 지도
- 여행 기록과 와인 기록 연결
- 맛 프로필 추천

## 화면 메모

- 한 화면에 질문 하나
- 큰 버튼 3–6개
- 상단에는 지금까지의 선택이 쌓임
- 하단에는 다음 질문이 더 정교해짐
- 지도는 별도 탭 또는 하단 영역에서 항상 보이게 유지

## 웹앱/모바일 구현 방향

- **하나의 웹앱**으로 만들고 모바일과 웹이 같은 동작을 하게 한다.
- 모바일은 네이티브 앱이 아니라 **웹뷰 / PWA / 반응형 웹**으로 맞춘다.
- 지도 인터랙션은 터치와 클릭이 모두 동일하게 동작해야 한다.
- 화면 크기에 따라:
  - 모바일: 질문 플로우 우선, 지도는 접힘/탭 전환
  - 웹: 지도와 폼을 나란히 보여줌
- 기술적으로는 동일한 상태 머신과 동일한 데이터 모델을 쓰는 게 좋다.

## 아직 열린 질문

- 세 개의 지도를 어떤 축으로 나눌까? 국가 / 지역 / 취향이면 충분할까?
- 와이너리 좌표는 자동 데이터셋으로 채울까, 수동 보정할까?
- 지도 색칠은 "마신 횟수" 기준일까, "새로 발견한 산지" 기준일까?
- 초보자용 표현과 전문가용 표현을 어디서 갈라야 할까?
- 블라인드 테이스팅 모드를 넣을까?
- 개인 취향 분석을 어느 시점부터 보여줄까?
- 와인 라벨/사진 입력은 보조 기능으로 둘까, 초반 핵심으로 둘까?
