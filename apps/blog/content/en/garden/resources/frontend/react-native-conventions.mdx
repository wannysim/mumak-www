Habits that work fine in web React can cause performance problems, layout breaks, or just an empty screen in RN. Here are the ones you'll hit often.

> Start with [[react-native-basics-for-react-devs|RN basics for React devs]] if you haven't.

## Lists are FlatList — use `.map` only for short ones

On the web, mapping over 100 items was fine. In RN, it's not.

```tsx
// ❌ scroll stutters and memory blows up
<ScrollView>
  {items.map((item) => <Card key={item.id} item={item} />)}
</ScrollView>

// ✅ only renders what's visible (virtualization)
<FlatList
  data={items}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => <Card item={item} />}
/>
```

**Why**: RN lists render as native views. Keeping off-screen views around eats memory and tanks scroll perf. `FlatList` keeps only the visible items + a small buffer and unmounts the rest.

**Rough cutoffs**:

- Items fit one screen (≈10) → `View` + `.map`
- A bit over one screen, short → `ScrollView` + `.map`
- Long or dynamic → `FlatList` (use `SectionList` for sections)

## Always set width/height on Image

On the web, the image had intrinsic dimensions and just unfurled. In RN, the runtime **can't know remote image dimensions ahead of time** — if you don't set them, it renders 0×0 (invisible).

```tsx
// ❌ invisible
<Image source={{ uri: 'https://...' }} />

// ✅
<Image source={{ uri: 'https://...' }} style={{ width: 100, height: 100 }} />
```

To fill the parent:

```tsx
<View style={{ width: '100%', aspectRatio: 16 / 9 }}>
  <Image source={{ uri }} style={{ width: '100%', height: '100%' }} resizeMode="cover" />
</View>
```

Local images (`require('./icon.png')`) ship with their dimensions, so they work without explicit sizing.

## Ignore Safe Area and the notch eats your UI

iPhone's notch, Dynamic Island, and bottom home indicator will overlap your UI.

```tsx
import { SafeAreaView } from 'react-native-safe-area-context';

export function Screen() {
  return <SafeAreaView style={{ flex: 1 }}>{/* draws around the notch and home indicator */}</SafeAreaView>;
}
```

There's a built-in `SafeAreaView` in `react-native`, but `react-native-safe-area-context` is more reliable and is the de facto standard. Expo projects typically have it preinstalled.

## Keyboard covers your input — KeyboardAvoidingView

Put a `TextInput` low on the screen and the keyboard will hide it when it opens.

```tsx
import { KeyboardAvoidingView, Platform, TextInput } from 'react-native';

<KeyboardAvoidingView behavior={Platform.OS === 'ios' ? 'padding' : 'height'} style={{ flex: 1 }}>
  {/* ... */}
  <TextInput />
</KeyboardAvoidingView>;
```

That `behavior` value behaves differently on iOS vs Android, which is genuinely annoying — but the pattern above is the standard fix.

## Taps use onPress, not onClick

```tsx
// ❌
<Pressable onClick={...}>

// ✅
<Pressable onPress={...}>
```

Not a typo — RN's tap event is `onPress`. `Pressable` is the modern choice; older `TouchableOpacity` / `TouchableHighlight` / `TouchableWithoutFeedback` are slowly being unified under `Pressable`.

## useEffect discipline — same as web React, but more important

The web React rule "[don't use Effects for everything](https://react.dev/learn/you-might-not-need-an-effect)" applies — and matters more in RN, because:

- Mount/unmount happens often as you navigate between screens
- A bad effect can open and close native modules (camera, location) repeatedly
- Memory leaks here directly drain device resources

**Anti-pattern — state derived from props**:

```tsx
// ❌
const [fullName, setFullName] = useState('');
useEffect(() => {
  setFullName(`${firstName} ${lastName}`);
}, [firstName, lastName]);

// ✅
const fullName = `${firstName} ${lastName}`;
```

**Anti-pattern — fetching with raw useEffect**:

Use React Query (`@tanstack/react-query`) instead. It works identically in RN.

useEffect is _genuinely_ needed for:

- External subscriptions (event listeners, native modules)
- Reacting to `AppState` changes (foreground/background)
- Real cleanup that has to happen

## Animations need `useNativeDriver: true`

Computing values per frame on the JS thread = jank. Tell native to do it.

```tsx
Animated.timing(opacity, {
  toValue: 1,
  duration: 300,
  useNativeDriver: true, // runs on the native side
}).start();
```

For anything non-trivial, use `react-native-reanimated` — it's the standard now.

## Memoize FlatList items

`FlatList`'s `renderItem` is called constantly during scroll. Wrap item components in `React.memo` and keep `keyExtractor`/`renderItem` references stable.

```tsx
const renderItem = useCallback(({ item }) => <Card item={item} onPress={handlePress} />, [handlePress]);

const keyExtractor = useCallback(item => item.id, []);

<FlatList data={items} renderItem={renderItem} keyExtractor={keyExtractor} />;
```

Same principle as the web, but jank at 60fps scroll is way more visible.

## Platform branching: split files, not if statements

Just like `if (isMobile)` clutter on the web, `Platform.OS === 'ios'` everywhere hurts readability.

**For small differences — Platform module**:

```tsx
import { Platform } from 'react-native';

const padding = Platform.OS === 'ios' ? 44 : 24;
```

**For meaningful differences — split files**:

```
components/
├── status-bar.ios.tsx
├── status-bar.android.tsx
└── index.ts          ← `import './status-bar'` picks the right one
```

Metro picks the right `.ios.tsx`/`.android.tsx` automatically.

## State and data layers are mostly the same as web

- Global state: Zustand, Jotai, Redux Toolkit — all work
- Server state: `@tanstack/react-query` — works
- Forms: `react-hook-form` — works (just use `TextInput`)

You can bring most of your web stack with you. **Only the component layer changes; the rest is the same.**

## Persistence isn't localStorage

The web's `localStorage` becomes:

- `@react-native-async-storage/async-storage` — key/value (simple stuff)
- `expo-secure-store` — sensitive data like tokens
- `expo-sqlite` / `op-sqlite` / `WatermelonDB` — real DB

The biggest gotcha: **everything is async** (`await getItem(key)`).

## Env vars are baked at build time

Like Next.js's `NEXT_PUBLIC_*`, Expo requires the `EXPO_PUBLIC_*` prefix to expose to the client. And they're **shipped inside the bundle, so never put real secrets there** (same rule as the web).

```ts
const apiUrl = process.env.EXPO_PUBLIC_API_URL;
```

## Text truncation is `numberOfLines`

The RN equivalent of `text-overflow: ellipsis`.

```tsx
<Text numberOfLines={2} ellipsizeMode="tail">
  long text...
</Text>
```

## z-index is unreliable

Especially on Android, `z-index` often doesn't behave as expected. **JSX order wins** — to be on top, render last.

```tsx
{
  /* in the back */
}
<Background />;
{
  /* on top */
}
<Overlay />;
```

`elevation` (Android) and `shadow*` (iOS) also influence stacking.

## Useful debugging tools

- **React DevTools**: `pnpm dlx react-devtools` — attaches to RN too
- **Flipper**: mobile-focused debugger (network, layout)
- **Reactotron**: lightweight RN-only debugger
- **Console**: `console.log` shows in the Metro terminal

## Checklist for new screens

- [ ] All text inside a `<Text>`?
- [ ] Long lists using `FlatList`?
- [ ] All `Image`s have width/height?
- [ ] Root has a `SafeAreaView`?
- [ ] No `TextInput` hidden by the keyboard?
- [ ] Is this useEffect really needed?
- [ ] All animations use `useNativeDriver: true`?
- [ ] Could platform branching be split files instead of `if`?
