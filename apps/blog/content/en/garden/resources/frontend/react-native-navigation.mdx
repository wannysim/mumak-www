How to bring your `react-router` (or Next.js file-based routing) instincts over to RN.

> Read [[react-native-basics-for-react-devs|RN basics]] first if you're new.

## The big picture — two choices

| Library                       | Mental model              | Web analogue       |
| ----------------------------- | ------------------------- | ------------------ |
| **React Navigation**          | Define navigators in code | react-router       |
| **expo-router** (built on it) | File-based routing        | Next.js App Router |

`expo-router` is a layer on top of React Navigation — same behavior expressed two different ways (code vs file structure). **This repo (`apps/mumak-native`) uses expo-router.**

## Three navigators

There are only three basic patterns for screen transitions.

### 1. Stack — push new screens, pop back

The most common. Tap an item in iPhone Settings and the next screen slides in from the right.

```
[Home] → push → [Detail] → push → [Edit]
                       ← back ← back
```

### 2. Tab — switch via a bottom tab bar

The big difference from Stack: **state is preserved.** Scroll inside the Home tab, switch to Profile, switch back — you're where you left off.

### 3. Drawer — side menu sliding from the left

The hamburger menu pattern. Increasingly out of fashion on mobile.

You typically **nest** these. Example: root is Tabs, each tab contains a Stack.

## Getting started with expo-router

Your file structure _is_ the route tree. Almost identical to Next.js App Router.

```
app/
├── _layout.tsx              ← root layout (Stack)
├── index.tsx                ← /
├── login.tsx                ← /login
├── (tabs)/                  ← group: doesn't appear in URL
│   ├── _layout.tsx          ← tabs layout
│   ├── home.tsx             ← /home
│   ├── profile.tsx          ← /profile
│   └── settings.tsx         ← /settings
├── posts/
│   ├── index.tsx            ← /posts
│   └── [id].tsx             ← /posts/123 (dynamic)
└── +not-found.tsx           ← 404
```

### Root layout

```tsx
// app/_layout.tsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack>
      <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
      <Stack.Screen name="login" options={{ presentation: 'modal' }} />
    </Stack>
  );
}
```

### Tabs layout

```tsx
// app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router';

export default function TabsLayout() {
  return (
    <Tabs>
      <Tabs.Screen name="home" options={{ title: 'Home' }} />
      <Tabs.Screen name="profile" options={{ title: 'Profile' }} />
      <Tabs.Screen name="settings" options={{ title: 'Settings' }} />
    </Tabs>
  );
}
```

### Navigating between screens

Practically identical to Next.js `<Link>` / `useRouter()`.

```tsx
import { Link, useRouter } from 'expo-router';

// Declarative
<Link href="/posts/123">Open detail</Link>;

// Imperative
const router = useRouter();
router.push('/posts/123');
router.replace('/login'); // replace the current screen
router.back(); // pop
router.dismiss(); // dismiss modal
```

### URL parameters

```tsx
// app/posts/[id].tsx
import { useLocalSearchParams } from 'expo-router';

export default function PostDetail() {
  const { id } = useLocalSearchParams<{ id: string }>();
  return <Text>Post {id}</Text>;
}
```

Query strings come through the same object. `/posts/123?ref=feed` works just like on the web.

## Getting started with React Navigation

If you're not using `expo-router`, you wire React Navigation directly.

```tsx
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';

const Stack = createNativeStackNavigator();

function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator>
        <Stack.Screen name="Home" component={HomeScreen} />
        <Stack.Screen name="Profile" component={ProfileScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}
```

Navigate via `useNavigation`:

```tsx
const navigation = useNavigation();
navigation.navigate('Profile', { userId: 123 });
```

`@react-navigation/native-stack` uses the real `UINavigationController` on iOS and `Fragment` on Android — **performance and motion match the OS**. Prefer it over the JS-based stack.

## Showing a modal

Don't use the core `<Modal>` for screen-level modals — use the navigation `presentation` option instead.

```tsx
// expo-router
<Stack.Screen name="new-post" options={{ presentation: 'modal' }} />
```

```tsx
// React Navigation
<Stack.Screen name="NewPost" component={NewPostScreen} options={{ presentation: 'modal' }} />
```

You get back gestures, swipe-to-dismiss, and the dimmed background for free.

## Customizing the header

```tsx
<Stack.Screen
  name="profile"
  options={{
    title: 'Profile',
    headerStyle: { backgroundColor: '#000' },
    headerTintColor: '#fff',
    headerBackTitle: 'Back',
    headerRight: () => <Button title="Save" onPress={...} />,
  }}
/>
```

To change it dynamically from within a screen:

```tsx
// expo-router
import { Stack } from 'expo-router';

<Stack.Screen options={{ title: title }} />;
```

## Deep linking

Open the app at a specific screen via a URL like `myapp://posts/123`.

```jsonc
// app.json (Expo)
{
  "expo": {
    "scheme": "myapp",
  },
}
```

In `expo-router`, file paths map to deep link paths automatically — `app/posts/[id].tsx` ↔ `myapp://posts/123`. Almost zero config.

To accept `https://` URLs as well (Universal Links / App Links), you need separate domain verification on iOS/Android.

## Common confusions

### "Why does my screen keep remounting?"

A screen pushed onto a Stack isn't unmounted — it's just sitting underneath. Pushing again creates a new instance. Tabs preserve mount state by default.

If you want to refresh data when a screen becomes visible again, use `useFocusEffect` or React Query's `refetchOnWindowFocus`:

```tsx
import { useFocusEffect } from 'expo-router';

useFocusEffect(
  useCallback(() => {
    refresh();
    return () => {
      // cleanup when leaving
    };
  }, [refresh])
);
```

### "Why does my tab lose state on switch?"

Default is preserve. If you've turned on `unmountOnBlur` (or similar), state will be lost. Check options if you didn't mean it.

### "Android back button doesn't do what I want"

Most cases are handled, but you can intercept it:

```tsx
import { BackHandler } from 'react-native';

useEffect(() => {
  const handler = BackHandler.addEventListener('hardwareBackPress', () => {
    if (isOpen) {
      close();
      return true; // we handled it
    }
    return false; // let default behavior win
  });
  return () => handler.remove();
}, [isOpen, close]);
```

### "Two headers showing"

Both parent (Stack) and child (Stack) are rendering a header. Disable one with `headerShown: false`.

## Mental model recap

- For `expo-router`: **think Next.js App Router**
- Screen-level modals: use `presentation: 'modal'`, not the core `<Modal>`
- Nest Stack / Tab / Drawer to build the app shape
- Refresh on focus via `useFocusEffect` or React Query
