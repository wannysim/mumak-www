A collection of notes that bridges the gap between "knowing how to use React" and "knowing why it was designed the way it is."

Everyone knows that calling `setState` updates the screen.
These notes cover what React compares in between, why it batches work together, and in what order it commits changes to the screen.

## Suggested Reading Order

Reading in the order Virtual DOM → Fiber → hooks → batching → memoization
follows the thread of "what does it compare → how does it schedule work → where does state live → when does it re-render → how does it cut work down."

Once you've covered the internals, move on to the practical patterns. The render/commit/paint
distinction from the batching note answers both "why does adjusting state from an effect arrive
one frame late" (the useEffect note) and "why does the mounted pattern flicker" (the hydration
note) — and the testing note is what lets you refactor toward those patterns with confidence.

If you need a JavaScript foundation, I recommend starting with [[frontend-javascript|How JavaScript Works]].
In particular, understanding hooks requires [[js-closure-and-scope|closures]] as prerequisite knowledge.
