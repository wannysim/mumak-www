# Stickerbook — 인터랙티브 개인 홈페이지 컨셉

최초 기록: 2026-10-27. 2026-10-29 사용자 요청으로 기존 디자인·화면·인터랙션 구현을 초기화했다. 2026-11-10 책상·소품·떼기 자국을 컨셉에서 뺐다. 2026-11-12 사용자 결정으로 닫힌 3D 책에서 시작해 펼쳐 들어가는 인터랙티브 개인 홈페이지로 방향을 넓혔다. 2026-11-13 책 안을 사진 잡지 연출로 바꾸고(폴라로이드·테이프·EXIF 제외), 나에 대한 정보는 잡지 문법으로, 스티커는 부록 시트로 옮겼다. 아래는 다음 디자인에서 이어갈 컨셉이며 **현재 구현된 기능 목록이 아니다**. 앱의 실행·검증 기반은 [implementation.md](./implementation.md), 재개 순서는 [NEXT.md](./NEXT.md)를 따른다.

## 핵심 경험

사이트에 들어오면 닫힌 책이 3D로 놓여 있다. 방문자는 책을 돌려 앞·뒤 표지와 책등을 구경하고, 책을 클릭하면 표지가 확 열리며 본격적으로 책 안으로 들어간다. 책 안에서는 사진 잡지를 넘기듯 주인이 찍은 사진을 한 장씩 보고, 잡지에 원래 있는 자리(러닝 헤드, 부록, 판권면)에서 주인에 대한 정보를 만지며 발견한다.

인터랙션이 많은 독립 개인 홈페이지다. 기존 Blog 사진전 홈 개편이나 Figma 작업의 재개, 공통 디자인 시스템 학습 단계의 완료를 뜻하지 않는다.

## 흐름

1. **닫힌 책 (진입):** 3D로 렌더링한 닫힌 책. 드래그로 돌려볼 수 있다.
2. **펼침 (전환):** 책을 클릭하면 표지가 열리며 책 안으로 들어간다. 드래그는 돌려보기, 클릭은 펼치기로 역할을 나눈다.
3. **책 안 (본편):** 좌우 펼침 페이지에서 사진을 넘겨 보고, 부록과 판권면에서 정보와 스티커를 만난다.

## 유지할 컨셉

- **표지 = fursona 명함:** 앞표지와 뒷표지가 fursona 명함의 앞면과 뒷면 역할을 한다. 닫힌 책을 돌려보는 이유가 된다. 각 면에 들어갈 정보는 다음 설계에서 정한다. (2026-11-12 대화에서 제안한 해석이며 사용자가 이의를 제기하지 않았다. 세부는 다시 확인한다.)
- **책과 페이지:** 펼치면 좌우 두 페이지가 보인다. 오른쪽 장을 넘겼을 때 그 뒷면은 다음 펼침의 왼쪽 페이지가 된다. 예를 들어 02쪽 뒷면은 03쪽이며 아래에서 04쪽이 드러난다.
- **페이지 넘김:** 잡은 위치를 따라 종이가 휘는 곡면 넘김을 유지한다. 진짜 책처럼 끌어서 넘길 수 있고, 사용성을 위해 클릭만으로도 페이지를 넘길 수 있어야 한다. 클릭 넘김도 같은 곡면 표현을 쓴다.
- **사진 (2026-11-13):** 웹으로 사진 잡지를 넘기는 연출. 한 페이지에 사진 한 장을 넉넉한 여백과 함께 놓고, EXIF·프레임·테이프 없이 이미지만 둔다. georgehatton.com의 레이아웃 감각을 참고한다.
- **나에 대한 정보 (2026-11-13):** 소개 문단 대신, 책 전체를 사진 잡지 한 권으로 보고 잡지에 원래 있는 자리에 넣는다. 화면에 잡지에 없는 UI를 만들지 않는 것이 "디자이너처럼 멋드러지게"의 기준이다.
  - **러닝 헤드:** 책 바깥 상단에 글자만 있는 한 줄(georgehatton.com 레이아웃 참고). 이름·한 줄 소개, 지금 상태 한 줄, 쪽 번호. 기존 "별도 헤더 없이" 선호와 부딪힌다고 알린 뒤 사용자가 방향을 승인했다. 항목과 문구는 아직 정하지 않았다.
  - **부록 레코드:** 잡지 부록 얇은 비닐 레코드처럼 뒤표지 안쪽 봉투에 꽂혀 가장자리가 살짝 삐져나온다. 닫힌 책을 돌려볼 때도 보인다. 끌어내거나 클릭하면 미끄러져 나와 돌고, 지금 듣는 Spotify 곡(재생 중이 아니면 마지막 곡)을 보여준다. 책에 끼워진 부록이므로 11-10에 뺀 "책상 소품"과 구분한다.
  - **판권면:** 마지막 페이지에 사진·카메라·사는 곳·서체·연락처를 같은 크기 평문으로 적는다.
- **스티커 (2026-11-13 부록으로 이동, 시험 중):** 사용자의 fursona 이미지, 흰 재단 테두리와 약간 비닐 같은 질감·광택. 사진 페이지에는 붙이지 않고 잡지 부록 같은 스티커 시트 페이지에 모은다. 핵심 컨셉이라 바로 빼지 않고 부록으로 살려 보지만, 프로토타입에서 미니멀·사진 잡지 컨셉과 어색하면 그때 뺀다(사용자 결정). 뗀 스티커를 다른 페이지에 붙일 수 있는지는 정하지 않았다.
- **떼는 동작:** 부록 시트에서 스티커를 떼어내는 동작은 유지한다. 떼는 강도에 따라 자국이 남는 표현은 하지 않는다. 뗀 뒤의 상태와 저장 범위는 다음 구현에서 정한다.
- **화면 대응:** 휴대폰의 가로·세로, 태블릿, Flip/Fold/Duo 등 화면 특성을 고려한다. 펼친 폴더블·Duo의 힌지는 책의 가운데 접힘과 겹치므로 좌우 펼침과 함께 설계한다. 특정 기기 지원은 실제 검증 범위를 구분해 기록한다.
- **호환성 (2026-11-12):** 여러 환경·디바이스·브라우저에서 동일한 동작을 매우 중요하게 본다. 핵심 동작(회전, 펼침, 드래그·클릭 넘김, 스티커 떼기, 사진 보기, 부록 레코드 꺼내기)은 모든 대상 환경에서 같은 규칙·같은 렌더 경로·같은 글자 모양이어야 한다. 화면 비율에 따른 레이아웃 적응은 허용한다. 특정 브라우저에서만 되는 최신 API는 결과가 같을 때만 최적화로 쓴다. 상세는 [tech-research.md](./tech-research.md) 0장.

## 컨셉에서 뺀 것

- **책상 배경 (2026-11-10):** 책 바깥의 무대를 두지 않는다. 화면은 책에 집중한다.
- **책상 소품 (2026-11-10):** 하스스톤 게임판 모서리처럼 발견하는 오브젝트 아이디어를 뺐다.
- **떼기 자국 (2026-11-10):** 조심스럽게 떼면 깨끗하고 세게 떼면 흔적이 남는 표현을 뺐다. 떼는 동작 자체는 유지한다.
- **폴라로이드·테이프·EXIF (2026-11-13):** 사진을 이미지만 두는 잡지식 페이지로 바꾸면서 프레임, 투명 테이프, 하단 EXIF 표시를 뺐다.

## 핵심 기술 쟁점

닫힌 책은 3D 렌더링이 필요하고, 책 안의 글자·사진은 선명도와 접근성을 위해 HTML이 유리하다. 이전 실험의 실패가 정확히 Canvas/WebGL과 HTML 사이 전환에서 글자가 줄고 흐려지는 문제였다([implementation.md](./implementation.md)). 펼쳐지는 순간 어디서 3D가 HTML로 넘어가는지, 곡면 넘김을 어떤 렌더러로 그리는지를 시각 방향이 정해진 뒤 작은 프로토타입으로 먼저 확인한다. 2026-11-12 조사 결과와 스파이크 계획은 [tech-research.md](./tech-research.md)에 있다.

## 이전에 밝힌 시각적 선호

이전 디자인 구현은 폐기했다. 아래는 사용자 선호 기록이며 새 디자인의 구체적인 배치·서체·치수·색상값을 확정한 것은 아니다.

- 미니멀하고 깔끔하게, 별도 헤더 없이 책이 중심. 2026-11-12 사용자가 ryo.lu 수준의 미니멀함·깔끔함·성능을 기준으로 제시했다. (2026-11-13 잡지 문법 승인으로 글자만 있는 러닝 헤드 한 줄은 두는 방향이다.)
- 2026-11-13 사용자가 georgehatton.com(그래픽 디자이너 포트폴리오)의 디자인 가이드를 많이 차용하자고 했다. 색은 따라가지 않고 레이아웃·타이포·여백·모션 원칙만 참고한다. 그 사이트는 정적인 사진 슬라이더지만 우리는 그 감각 위에서 인터랙티브하게 구현한다. 관찰 내용은 아래 참고 자료에 있다.
- 성능은 디자인의 일부다. 첫 화면은 가볍게 그리고, 무거운 자원은 클릭 전에 미리 준비해 펼침이 즉시 반응하게 한다. 구체적인 예산 수치는 프로토타입에서 ryo.lu 체감과 비교해 정한다.
- 흰색을 넓게 쓰고 주황·크림슨 레드는 작은 포인트. 처음 언급한 6:3:1을 화면 면적에 강제하지 않는다.
- 사진 자체의 색은 제한하지 않는다. (테이프 선호는 2026-11-13 테이프를 빼면서 효력이 없어졌다.)
- 기존 JPG 6개는 유지한다. 실제 사용자 사진·fursona 자산은 아직 연결하지 않았다.

## 다음 설계에서 다시 정할 것

닫힌 책의 형태·재질·조명, 표지(명함) 앞뒷면 정보, 펼침 연출과 3D→HTML 전환 지점, 책 안의 화면 구성과 비율, 책 바깥 여백의 처리, 서체·그림자, 사진 페이지의 여백·비율과 사진을 충분히 감상할 크기, 러닝 헤드 항목, 부록 레코드 연출과 Spotify 연결 방식, 판권면 항목, 부록 스티커 시트 구성과 뗀 스티커의 행방, 곡면 넘김 렌더러와 제스처, 소리·상태 저장은 새 디자인에 맞춰 결정한다.

페이지 넘김은 사용자가 잡은 위치를 따르는 느낌이 중요하다. 누르는 순간 레이아웃이나 글자 크기·선명도가 바뀌지 않아야 한다. 키보드·터치·동작 줄이기와 충분한 조작 영역도 설계에 포함한다. 이전 구현의 물리 수치와 기하학 방식을 그대로 재사용해야 한다는 뜻은 아니다.

## 참고 자료

### ryo.lu (2026-11-12 사용자 제시)

사용자가 원하는 감각에 가장 가까운 레퍼런스다. 2026-11-12 화면과 CSS를 직접 확인한 관찰이다.

- **앞면은 극단적으로 덜어냄:** 흰 바탕에 큰 산세리프 한 문장("Ryo is exploring Taipei.")과 작은 모노스페이스 대문자 상태 줄, 링크 몇 개뿐이다. 소개 문단 없이 실시간 상태 한 줄과 말장난으로 성격을 드러낸다.
- **전환은 물리적 비유 하나:** 오른쪽 위 모서리가 CSS 그라데이션·그림자로 만든 말린 종이다. 아래에 ryOS iframe이 120px 영역만 `clip-path`로 보이고, 누르면 0.65s `cubic-bezier(.16,1,.3,1)`로 전체 화면까지 펼쳐진다.
- **뒷면은 극단적으로 채움:** [ryOS](https://os.ryo.lu)는 레트로 데스크톱 OS다. 자기 정보가 About 페이지가 아니라 iPod·Photo Booth·Journal·Stuff 같은 직접 굴려보는 앱으로 들어 있다.

- **가벼운 체감의 근거 (2026-11-12 데스크톱 Chromium 측정):** 앞면은 CSS 7KB, 서브셋 woff2 2개(각 18KB), 이미지 0개다. JS 번들은 323KB(전송 기준)로 작지 않다. 체감 속도는 첫 화면에 그릴 것이 거의 없고, 전환을 `clip-path`·`transform`으로만 처리하고, 무거운 ryOS iframe을 처음부터 모서리 뒤에 미리 로드해 클릭 즉시 열리는 데서 온다. 총 용량이 작아서가 아니다.

이 앱에 가져올 것은 원리다: 진입은 덜어내고 안쪽은 채우는 대비, 정교한 전환 하나, 정보를 장난감으로 만들기, 카피에 성격 담기. ryOS의 레트로 OS 외형을 재현하지 않는다. [ryOS 소스](https://github.com/ryokun6/ryos)는 **AGPL-3.0**이므로 코드를 가져오지 않는다. ryo.lu 앞면 소스는 공개되지 않았다.

### georgehatton.com (2026-11-13 사용자 제시)

그래픽 디자이너 George Thomas Hatton의 포트폴리오. 사용자가 기억한 "책 펼침 화면"은 2021–2023년 버전(WordPress 테마 "George the Second", 제작 Kasper Nordkvist)이다. 현재 사이트는 다른 디자인이다. 2026-11-13 Wayback Machine 스냅샷 `20230923132636`의 HTML·CSS·JS를 받아 읽고 Chromium으로 띄워 확인했다. 아카이브에는 전체 크기 사진이 없고 20×13 흐린 미리보기만 남아 있어서, 실제 모습은 사용자가 준 스크린샷으로 본다.

**구조 관찰:** 책은 3D가 아니라 사진이다. 회색 배경 위 실물 책 펼침면을 찍은 1920×1280 JPG를 `object-fit: cover`로 화면 전체에 깔고, keen-slider로 넘긴다. 번들에 canvas·WebGL·CSS 3D 코드는 없다. 페이지 배경이 따로 있는 게 아니라 사진의 배경지가 곧 화면 배경이다. 넓은 화면에서 잘려도 책이 안 잘리도록 사진 자체를 여백 넉넉하게 찍었다.

| 헤더      | 배경 없는 텍스트 한 줄을 3단으로: 이름+직함(폭 27%), 연락처, 오른쪽 끝 Information. `mix-blend-mode: difference` + `grayscale(1)`이라 밝은 사진 위에선 검게, 어두운 사진 위에선 희게 보인다(캡처로 확인). 550px 이하에선 직함·연락처를 숨긴다. | 책 장면 위에 얹는 최소 정보 줄. 배경·그림자 없이 대비를 확보.                        |
| 색        | 글자는 흑/백뿐, 자리표시 `#ddd`, 색은 전부 사진에서 온다.                                                                                                                                                                                      | 2026-11-13 사용자 결정: 색은 따라가지 않는다.                                        |
| 넘김 조작 | 화면 양옆에 높이 100%짜리 클릭 기둥(데스크톱 약 52px 폭)을 두고, 글리프는 얇은 선 화살표 1rem. 작품 목록에선 이미지 좌우 30% 영역에 화살표 커서. 슬라이더 자체는 `pointer-events: none`이라 드래그가 없다.                                     | 클릭 넘김 영역을 페이지 높이 전체로 크게, 표시는 작게. 드래그 곡면 넘김과 공존 설계. |
| 쪽 표시   | 제목 줄 오른쪽 끝에 `1/11`.                                                                                                                                                                                                                    | 쪽 번호 `03/24` 같은 한 줄 표기.                                                     |
| 메타 정보 | "Brand Identity, Website, Printed Material" 쉼표 나열, "Client: X". 표나 태그 칩 없이 평문.                                                                                                                                                    | 나에 대한 정보 문구도 라벨·칩 없이 평문으로.                                         |
| 모션      | 적고 느리다. 슬라이드 1000ms·4초 자동 넘김, 페이지 전환은 내용 페이드아웃 400ms(out-cubic) 뒤 페이드인 400ms(in-cubic), 첫 진입은 750ms 뒤 750ms 페이드인. 링크 hover는 `opacity .2`(0.3s). 탄성·바운스 없음.                                  | 전환 수를 줄이고 각 전환을 길고 차분하게.                                            |
| 성능      | 20×13 미리보기를 배경으로 먼저 깔고 lazysizes로 343/686/960/1334/1920px 중 맞는 사진을 받는다. 폰트 파일 1개(약 68KB).                                                                                                                         | 사진 해상도 단계와 흐린 미리보기.                                                    |
