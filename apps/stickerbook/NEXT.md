# Stickerbook 개발 재개

기준: 2026-10-29. 사용자가 기존 디자인에 만족하지 않아 **컨셉과 개발 기반만 남기도록 요청했다.** 현재 화면은 빈 흰 바탕이다. 이전 디자인을 다듬는 단계가 아니라 새 시각 방향을 정하는 단계다.

## 현재 상태

- 작업 브랜치: `feature/stickerbook-concept`. 재개 시 실제 브랜치·작업 트리·원격 상태를 확인한다. `develop`에 직접 push하지 않는다.
- 남은 것: [컨셉](./plan.md), React/Vite·TypeScript·Tailwind 실행 기반, lint·format·단위/E2E·coverage·CI 설정, 샘플 JPG 6개와 출처.
- 제거한 것: 책상·책·폴라로이드·스티커·소품 UI, 넘김·떼기·확대·접힘 화면 대응 로직, 전용 스타일·폰트·여우 자산, 관련 테스트.
- 실행: `pnpm --filter stickerbook dev`. 로컬 `http://stickerbook.mumak.localhost:1355`, 모바일은 Vite 로그의 Network 주소. 빈 화면은 의도한 상태이며 오류가 아니다.
- 이전 작업은 `e708e3e`에 보존돼 있다. [개발 기반과 교훈](./implementation.md)을 참고하되 이전 구현·검증 숫자를 현재 기능으로 취급하지 않는다.

## 다음 작업

1. 루트 `AGENTS.md`, 이 문서, `plan.md`를 읽는다.
2. 사용자가 다시 시작할 때 새 시각 방향을 함께 정한다. 미니멀한 흰 바탕·주황/크림슨 포인트 선호는 기록으로 보존했으며, 구체적인 배치·서체·크기·재료감은 새로 결정한다.
3. 책상과 좌우로 펼친 책의 정지 화면부터 비교하고 사용자 판단을 받는다. 폐기한 디자인을 그대로 복원하거나 독자적으로 새 디자인을 확정하지 않는다.
4. 시각 방향이 정해지면 자연스러운 넘김과 앞뒤 면 연결, 사진·EXIF, 스티커와 소품, 화면별 동작을 순서대로 검토한다. 구현 수단과 세부 수치는 재선택한다.

## 유지할 경계

- 독립 사진 전시 앱이다. Blog 사진전 홈 개편과 Figma는 계속 보류한다.
- JPG는 유지하고, 실제 fursona 자산과 EXIF 파이프라인은 추후 연결한다.
- 펼치면 두 페이지, 넘기는 장 뒷면은 다음 펼침의 왼쪽이라는 컨셉은 유지한다.
- 사용자 판단 전에 디자인을 확정하거나 디자인 시스템 단계 1 전체를 완료했다고 취급하지 않는다.
- 이전 픽셀 비교·기기 에뮬레이션 결과는 삭제된 프로토타입의 기록이다. 실기기 호환성을 입증하지 않는다.

검증 명령은 [README](./README.md)를 따른다. 현재 테스트는 앱 개발 기반의 부팅만 검사하며 책이나 스티커 동작을 지원한다고 주장하지 않는다.

## 초기화 후 검증 (2026-10-29)

타입·lint·format·단위 1개·빌드·Knip 통과. Chromium·Firefox·WebKit에서 데스크톱/모바일 부팅 E2E 6개 통과. JPG 6개는 초기화 전후 SHA-256이 동일하다. 이 결과는 빈 앱의 개발 기반에 대한 검증이다.
