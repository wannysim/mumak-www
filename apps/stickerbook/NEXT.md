# Stickerbook 개발 재개 메모

기준: 2026-10-27. 사용자가 현재 개발 내용을 저장하고 나중에 이어가기로 했다. 작업 브랜치는 `feature/stickerbook-concept`, 통합 대상은 `develop`이다. 이 문서는 진행 중인 프로토타입의 인계 기록이며 디자인 최종 승인이나 출시 완료를 뜻하지 않는다.

## 다음 세션에서 먼저 할 일

1. 루트 `AGENTS.md`, 이 문서, [motion.md](./motion.md)를 읽고 브랜치·작업 트리·원격 상태를 확인한다. `develop`에 직접 push하지 않는다.
2. `pnpm install` 후 `pnpm --filter stickerbook dev`로 실행한다. 주소는 `http://stickerbook.mumak.localhost:1355`. 모바일은 같은 네트워크에서 Vite 로그의 `Network` 주소를 사용한다. 내부 포트와 IP는 재시작·네트워크에 따라 달라지므로 이전 세션 주소를 고정하지 않는다.
3. 최신 HTML 넘김을 사용자가 실제 기기에서 다시 확인하도록 한다. 아직 최종 시각적 승인을 받은 상태는 아니다. 완료 범위를 처음부터 재조사하기보다 아래 관찰점부터 이어간다.
4. 후속 작업은 사용자와 정한다. 추천 순서는 넘김 감각·선명도 확인 → 작은 화면의 두 페이지 감상성 → 실제 사진·fursona·EXIF 연결이다. 새 범위를 이미 승인받은 것으로 취급하지 않는다.

## 유지할 사용자 의도

- 책상 위 스티커북이 주인공인 별도 사진 전시 앱. 기존 Blog 사진전 홈 개편이나 Figma 작업의 재개가 아니다.
- 흰색을 넓게 쓰고 주황·크림슨은 작은 포인트. 처음 말한 6:3:1을 화면 면적의 엄격한 비율로 적용하지 않는다. 헤더 없이 미니멀하게 유지한다.
- 폴라로이드 사진 하단은 EXIF. 없는 정보를 만들어내지 않는다. 현재 샘플은 `EXIF 미제공 · 샘플 사진`이다.
- 페이지마다 작고 불규칙하게 배치한 스티커 2–3개, 투명한 테이프와 다양한 각도. 배치는 재렌더링할 때마다 랜덤하게 바뀌지 않는다.
- JPG 6개는 그대로 유지한다. 사용자의 fursona는 아직 제공되지 않아 임시 여우 SVG를 사용한다.
- 펼치면 모바일도 좌우 두 페이지다. `01–02`의 오른쪽 02쪽을 넘기면 뒷면 03쪽이 왼쪽에 놓이고, 아래에 있던 04쪽이 오른쪽에 남는다. 역방향도 같은 장을 뒤집는다.
- 페이지 전체가 가로로만 회전하는 느낌, 잡는 순간 레이아웃이 바뀌거나 글자·해상도가 갑자기 줄어드는 현상을 피한다.
- 공유 디자인 시스템의 역할별 token을 조기 통합하거나 학습 단계 1 전체를 완료한 것으로 취급하지 않는다.

### 렌더러를 바꾼 이유

최초 구현은 HTML을 수동 Canvas 텍스처로 다시 그려 Three.js 곡면에 올렸다. CSS의 최소 10px 글자와 Canvas의 논리 폭 480/글자 12px이 달라 작은 화면에서 넘길 때 글자가 축소됐다. 고정 텍스처와 DPR 제한도 있었다. 누르기만 한 상태의 화면을 유지하는 수정만으로는 이동 중 품질 문제가 해결되지 않았다.

현재는 별도 비트맵 전환과 이 앱의 Three.js 의존성을 제거했다. `page-texture.ts`, `turn-surface.ts`, 이전 `paperPoint`는 삭제된 경로다. 다시 도입하기 전에 같은 문제가 재발하지 않는 증거가 필요하다. 결정은 [D-019·D-020](../../docs/design-system/decision-log.md)에 남아 있으며 D-019는 최초 실험, D-020이 현재 선택이다.

## 남은 한계와 관찰점

- **중앙 국소 변형:** 위·아래 모서리는 대각선으로 접히지만 정중앙을 수평으로 당기면 세로 접힘이 된다. 중간만 움푹 휘는 탄성은 현재 구현하지 않았다.
- **곡면 근사:** 연속 그라데이션으로 명암 띠를 줄였지만 사진의 곡면 경계는 유한한 띠로 근사한다. 브라우저의 변형 안티앨리어싱까지 모든 픽셀을 동일하게 보장하지 않는다.
- **작은 펼침:** 320px 화면에서도 두 페이지와 44px 스티커 대상은 유지된다. 사진은 확대할 수 있지만 두 페이지 감상 크기의 만족도는 사용자 판단이 남아 있다.
- **실기기 성능:** 폴더블·태블릿·iPhone Duo 실물, 저사양 기기의 프레임·전력, OS 확대·VoiceOver 음성 출력은 검증하지 않았다. viewport/CDP 에뮬레이션을 실기기 검증으로 표현하지 않는다.
- **콘텐츠 연결:** 실제 사용자 사진·fursona와 EXIF 추출·저장·표시 항목 정책은 미완료다. 현재 소품·스티커 표현도 프로토타입이다.
- **상태 저장:** 스티커 변화는 메모리 상태여서 새로고침하면 초기화된다. 책상으로 떼어 옮기기, 위치 재배치, 영구 저장, 소리는 구현하지 않았다.
- **공개:** 이 저장 시점에는 작업 브랜치 push만 요청받았다. PR·develop 병합·배포는 별도 요청이 필요하다.

## 검증 기준선

최신 런타임 변경 이후 실행한 결과:

- `check-types` → `lint` → `format:check` → `test:ci` → `build` 통과. 단위 41개, coverage statements 97.24%, branches 92.27%, functions 97.4%, lines 99.31%.
- `CI=1 pnpm --filter stickerbook exec playwright test --workers=2`: Chromium·Firefox·WebKit 합계 **29 passed / 4 skipped**. 제외한 4개는 Chromium CDP 구획·터치 시나리오의 Firefox/WebKit 실행이다.
- `pnpm exec knip --workspace apps/stickerbook` 통과. JPG 6개는 수정 전후 SHA 해시 동일.
- 양방향 진행률 0.015·0.3·0.65·0.96·1에서 폰트 크기·프레임 너비·뒷면 방향을 검사한다. DPR 3 모바일 포함.
- 별도 Chromium 픽셀 비교에서 1440px/DPR 2, 390px/DPR 3, 320px/DPR 3의 아직 접히지 않은 EXIF 영역은 진행률 0.015에 차이 0. 전체 착지 화면에는 모서리 표시·그림자·안티앨리어싱 차이가 있으므로 전체 픽셀 일치를 주장하지 않는다.
- 독립 verifier가 이동 중 크기와 앞뒷면 연결을 확인했다. 중앙 국소 변형과 곡면 근사의 한계도 함께 기록했다.

현재 구현을 바꾸지 않고 문서만 이어 쓰는 경우 위 검증을 처음부터 반복할 필요는 없다. 런타임 변경 시 관련 회귀와 CI preflight를 다시 실행한다. 로컬 기본 E2E 명령만으로 전체 브라우저를 검사했다고 주장하지 말고 위 `CI=1` 명령을 사용한다.
