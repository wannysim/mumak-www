# 라이브 코딩 학습 범위

조사일: 2026-11-01. 실제 시험 문제를 복제하거나 유출 문제를 수집하지 않았다. 공개 채용 안내가 확인해 주는 준비 범위와 이 앱의 자체 학습 설계를 구분한다.

## 공식 근거

- [토스플레이스 Frontend Developer](https://toss.im/career/job-detail?job_id=5311744003): 1차 직무 인터뷰에 라이브코딩 포함. React·정적 타입·복잡한 요구사항의 추상화를 요구하며 테스트 도구로 Jest/Vitest를 안내한다. 알고리즘/React 출제 비율, 구체 문제, 제한 시간은 이 공고에서 확인되지 않는다. 이전에 공유된 4071101003 공고 URL은 이번 조회에서 본문을 얻지 못했다. 같은 직무의 현재 확인 가능한 공고를 참고했으며 채용 초대의 안내가 우선이다.
- [Microsoft technical interviewing](https://careers.microsoft.com/v2/global/en/hiring-tips/technical-interviewing): 문제 이해·계획·실제 코드·테스트·복잡도 설명을 평가한다. 배열/문자열, 큐, 연결 리스트, 트리/트라이, 해시, 그래프를 자주 다루는 자료구조의 예로 제시한다.
- [Amazon FEE interview preparation](https://amazon.jobs/content/en/how-we-hire/fee-interview-prep): 실행 가능한 프론트엔드 코드, 경계값, 유지보수성과 테스트를 강조한다. 프론트엔드 설계에서는 사용성·성능·접근성·보안·확장성을 다룬다.
- [Amazon software development topics](https://amazon.jobs/content/en/how-we-hire/interview-prep/software-development-topics): 자료구조/알고리즘과 코딩·화이트보드 설계를 준비하라고 안내한다. 세부 형식은 채용 담당자에게 확인하도록 한다.

공개 근거로 특정 회사의 실제 빈도 순위를 만들 수 없다. 슬라이딩 윈도우 및 단계별 연결 리스트 집중 경로는 사용자가 직접 경험한 면접에서 어려웠던 주제에 맞춘 선택이다. 난이도와 시간은 앱의 연습 기준이며 토스의 공식 평가표나 합격선이 아니다.

## 학습 설계

| 분류              | 문제                                                                             | 학습 초점                           |
| ----------------- | -------------------------------------------------------------------------------- | ----------------------------------- |
| 배열·해시         | 장바구니, 최초 이벤트 유지, 목표합 구간 개수                                     | 계약·정수·중복·prefix               |
| 슬라이딩 윈도우   | 고정 길이 최대합 → 양수 최소합 길이 → 중복 없는 최장 → 최대 K종 → 최소 포함 구간 | 두 포인터·빈도·단조 이동 증명       |
| 연결 리스트       | 직접 구현 → 참조 역순 → 순환 입구 → 이중 덱 → LRU → random 깊은 복사             | 실제 객체 참조·불변식·자료구조 조합 |
| 스택·큐           | 괄호, 다음 큰 값                                                                 | 스택·분할 상환 분석                 |
| 탐색·정렬         | lower bound, 구간 병합                                                           | 반열린 구간·정렬 비용·입력 보존     |
| 트리·그래프       | 레벨 순회, 최단 간선 수, 의존성 순환                                             | BFS·방문 시점·위상 정렬             |
| 힙                | 스트림 k번째 큰 값                                                               | 제한된 메모리·sift up/down          |
| DP·백트래킹       | 동전, 조합                                                                       | 그리디 반례·상태/점화식·가지치기    |
| 프론트엔드·비동기 | 동시 실행 큐, 검색 reducer, 이벤트 구독                                          | 경합·불변 스냅샷·구독 정리          |

기본은 단일 패턴과 경계값, 실전은 불변식/비용/상태 변화, 심화는 조합과 확장이다. 5분은 계약 확인, 10분은 그림/예시 추적, 15분은 설계와 코드 일부를 작성한다. 전체 구현은 15~45분(기초 몸풀기 10분)을 권장한다. 미완성 코드와 화이트보드 텍스트 메모를 저장하고 다른 기기에서 이어 쓴다.

## 검증과 한계

- 모든 문제에 시작 코드, 계약, 예시, 힌트, 정답 코드, 복잡도, 추가 질문을 제공한다.
- 연결 리스트는 Worker에서 실제 노드를 만들고 참조/입력 보존/prev/tail/size를 검증한다. LRU는 기능 결과를 검사하고 O(1) 구조 선택은 별도 설명·검토로 확인한다.
- 자동 테스트는 제공된 사례의 기능 검증이다. 2초 제한 통과만으로 점근 복잡도나 전체 정답을 증명하지 않는다. 힙 대신 전체 정렬한 풀이처럼 결과만 맞는 구현은 비용 설명 단계에서 구분한다.
- 프론트엔드 문제는 JavaScript 로직 실행이다. JSX 렌더링 환경은 포함하지 않는다. React 상태·effect·접근성 질문과 경험 메모로 보완하며 실제 UI 라이브코딩 연습은 별도의 프로젝트/IDE에서도 진행한다.
- 노트와 코드의 개별 길이 제한 외에 전체 백업 2MB 제한을 유지한다. 서버로 넘기는 원문 코드를 실행하지 않으며, 브라우저의 격리 Worker에서만 실행한다.

### 기초에서 가변 창으로 연결하기

합계 누적과 Set·Map의 역할, 연속 구간의 양 끝과 길이를 먼저 설명한다. 양수 최소합 문제는 조건을 만족하는 동안 줄이며 최소 길이를 기록하고, 최대 K종 문제는 조건을 위반하는 동안 줄인 뒤 최대 길이를 기록한다. 각 문제에 한 입력을 순서대로 추적한 그림과 경계 테스트를 두어 두 축소 규칙을 비교한다. 양수 계약과 문자 빈도 0에서의 키 제거를 별도로 점검한다. 두 문제의 모범답안은 길이 0~4의 작은 입력 전체를 독립 완전탐색 결과와 대조하며, 한 번만 축소·등호 누락·빈도 유실 오답을 회귀 검사한다.
