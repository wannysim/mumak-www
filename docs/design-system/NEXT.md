## A. 지금 막고 있는 것

단계 1로 넘어가려면 이것부터. 위에서 아래 순서로 하면 된다.

### A-4. 5분 문제 설명 녹화 + 자기 비평 · 30분

`plan.md` 1주차 주말 항목. 녹화 자체보다 **"기술 이름만 말하는 구간"이 어디인지 스스로 잡는 것**이 목적이다. 잡히면 A-2로 돌아가 고친다.

설명할 대표 흐름은 “큰 사진 한 장에 관심을 느낌 → 사진을 선택 → 사진 전용 전시 탐색”으로 정했다. 이 흐름이 사람에 대한 호기심으로 이어지는 이유와 예상되는 약점을 본인이 설명한다. 대화에서 비평을 준비하더라도 실제 녹화·자기 비평을 수행하기 전에는 완료로 표시하지 않는다.

첫 비평은 기록했다: 깔끔하게 완성하지 못하면 누구인지 알기 전에 음악·와인을 자랑하는 화면으로 느껴질 수 있다는 우려다. 본인의 예상이라는 점을 구분해 `home-direction.md`에 보존했다. 전체 설명 녹화와 그에 대한 자기 비평은 아직 남아 있다.

대화에서 선택한 소개 문구는 “개발하고 사진 찍는 심완입니다.”다. 큰 사진과 짧은 소개로 사람에게 관심을 갖게 한다는 방향은 유지하지만, 시안의 소개 문구·레이아웃·위젯·반응형·헤더/푸터 변경과 관련 테스트는 모두 원복했다. 구체적인 디자인은 재검토하며 현재 코드의 계약으로 취급하지 않는다. 대표 사진과 전시 페이지, 와인·AI 데이터 연동, 음악의 주간 집계는 아직 준비되지 않았다.

## B. 끝나면 단계 1로

A가 전부 닫히면 `plan.md` §8 "단계 1 — 최소 수직 절편"과 §9 2주차로 넘어간다. 2026-09-18에 정리한 홈의 목적에 맞춰 사진 중심의 탐색 흐름을 구체화하고, 아래 기존 구현 순서와 지원 대상이 그 경험을 검증하는 데 맞는지 재평가한다. 사진전의 상세 표현과 연동 설계는 단계 0 완료 조건에 추가하지 않는다.

1. **`--ring` light 대비 수정** — 확인된 유일한 접근성 결함. 2.82:1을 3:1 이상으로. `--accent-foreground`(7.92:1)가 이미 있으니 값 후보는 그 근처
2. **motion token 최소 집합** — easing 4종이 손으로 쓰였고 karaoke/blog가 곡선까지 다르다. 소비처 2곳 이상이 확인된 유일한 축
3. **`Button` / `ContentCard` 수직 절편** — Figma Variables까지 연결하고, D-010에 따라 공통 foundation을 사용하는 최소 Storybook으로 포커스 preset·상태를 검증한다. 자동 a11y 검사와 실제 Tab 이동, 표시 대비·잘림·가림 확인을 함께 다룬다

손대지 않기로 이미 정한 것: type / spacing token (`decision-log.md` D-005), `packages/ui`의 안 쓰이는 29개.
